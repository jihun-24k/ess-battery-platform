## UI001 — 실행 로그를 읽는 정적 운영 대시보드

2026-10-17. 현재 Python MVP의 실제 검증 실행 네 건을 `dashboard/export_data.py`로 내보내고, HTML/CSS/JavaScript에서 조회·재생한다. 백엔드가 없는 단계에서도 데이터 수집 → ML 추론 → 문서 조회 → 모의 대응 흐름을 학습할 수 있다. 배치 선택, 윈도 재생, 사건 필터와 상세 조회를 지원한다. 로컬 절대 경로와 모델 파일·원천 MAT는 배포하지 않는다.

대안은 API 서버와 프런트엔드 프레임워크를 동시에 도입하는 것이다. 현재 데이터는 과거 실행 결과이므로 정적 화면으로 시작해 의존성과 운영 부담을 줄였다. 대신 실시간 수집·재학습·새 추론은 수행하지 않으며 데이터를 갱신하려면 다시 export해야 한다. UI의 서버 상태는 현재 연결되지 않음/기록 재생/모의 동작으로 표시한다. 배포는 소유자 전용 비공개 Sites를 사용한다. 브라우저 접근이 거부되어 렌더링 검증은 하지 못했고, exporter와 순수 JavaScript 상태 처리 테스트를 실행했다.

## RT001 — 새 스트리밍 패키지와 독립 프로세스

2026-10-17. 사용자 서버 구성에 따라 `ess_platform`을 신설했다. 기존 MAT ETL 소스가 현재 없어 이를 추측해 복원하지 않고, 새 합성 JSONL 계약과 PostgreSQL/HTTP로 독립 실행한다. 수집·ML mock·운영 API는 표준 `http.server`, 추론·대응은 별도 CLI 워커다. 대안 FastAPI/메시지 브로커는 현재 제외 요청과 학습 범위를 고려해 도입하지 않았다. 표준 서버는 loopback 학습용이며 외부 운영 서버 역할을 목표로 하지 않는다.

## RT002 — DB polling과 영속 상태로 멱등성·재시작 보장

측정 source/event_id, 추론 measurement_id, 조치 incident_id, 알림 dedup_key를 unique로 제한한다. 원본 payload와 hash를 보존하며 같은 ID의 다른 값은 409로 거부한다. 연속 판단·가상 냉각·재시도 상태를 메모리 대신 DB에 저장한다. 워커 transaction/advisory lock은 처리 순서를 단순화하지만 동시 처리량과 가장 오래된 재시도 작업의 대기 비용이 있다. 향후 자산별 파티션이 대안이다. 콘솔 outbox는 at-least-once이며 실장비 exactly-once 보장을 주장하지 않는다.

## RT003 — 시간 순서, 지연 데이터, 대응 취소

대기 데이터는 관측 시각 순으로 처리하되 이미 추론한 watermark 이하 데이터는 late로 격리한다. 재정렬 대기 버퍼·과거 추론 재계산은 구현하지 않는다. 시연 정책은 이상 연속 2회/정상 연속 3회, 30초 초과 간격·모델 버전 변경 시 카운터 초기화다. 패턴 복귀 전 미실행 조치는 취소한다. 실제 안전 임계값과 장애 해소를 의미하지 않는다.

## RT004 — ML과 학습·평가·모델 저장소도 명시적 mock 계약

ML 서버는 최근 온도와 데모 설정 임계값 차이를 반환한다. 별도 `train-mock`은 모델 fitting 대신 설정 후보·데이터 cutoff와 경계 계약 테스트를 저장한다. 실제 성능 지표는 null이다. `approve-model`만 active 포인터를 바꾸고, 추론에는 사용 버전을 고정 기록한다. 자동 재학습/자동 배포는 구현하지 않는다. 실제 모델 전환 시 mock 필수 검증과 특징·평가 계약을 함께 교체한다.

## RT005 — 학습 문서 snapshot, 고정 정책, 로컬 관제

문서 내용/hash/정책 버전을 사건에 저장한다. 문서 누락·변조, 허용 목록 외 동작은 차단한다. 허용 명령은 DB 가상 냉각 boost이며, 알림은 DB outbox와 콘솔이다. 운영 API의 로컬 관제 화면은 실제 DB를 조회하고 이전 Sites 화면은 과거 로그용으로 유지한다. 외부 DB 공개나 임의 실장비 명령은 추가하지 않는다. 브라우저 QA는 접근 거부로 미검증이며 PostgreSQL/HTTP·상태 렌더링 테스트로 확인한 범위를 문서화한다.

## RT006 — 서버별 모듈화와 필요한 회귀 테스트 통합

2026-10-17. 사용자 요청에 따라 수집·추론·운영 역할을 `collection/`, `inference/`, `operations/`로 나눴다. 공유하는 HTTP 입출력·클라이언트·잠금만 최상위 공통 모듈로 분리했다. `api.py`·`workers.py`의 중복 정의와 예전 import 경로를 제거하고 CLI도 parser·worker loop·진입점으로 나눴다. 대안인 범용 repository/DI 계층은 현재 규모와 Python 학습 목적에 불필요해 사용하지 않았다.

Python 파일 및 함수에 한국어 역할·입출력 docstring을 추가했다. 과거 ETL/MVP 테스트는 현재 실행 경로와 맞지 않아 삭제/대체했고, 현재 플랫폼과 두 대시보드의 유효한 회귀 테스트는 `tests/`에 기능별로 통합했다. 기본 pytest 수집을 복구했으며 동작 보장에 필요한 실패·동시성·멱등성 테스트는 유지했다. 실행할 수 없는 과거 CLI 등록과 wheel 패키지 경로를 정리하되 과거 소스와 실행 기록은 보존한다. 새 import 경로가 필요한 변경이므로 `platform-refactoring.md`에 대응 경로를 문서화한다.

## AG001 — 제안: bounded 단일 Agent와 검증된 대응 제안

2026-10-17. 아직 구현·승인되지 않은 확장 설계다. 동적인 조사와 Tool 선택은 LLM, 사건·권한·승인·실행 상태는 Python이 담당한다. 읽기 Tool과 제안 Tool을 Agent에게 제공하고 실제 실행 함수는 executor만 호출한다. shadow 모드에서 시작해 실제 LLM Tool 선택을 평가한 후 assisted 모드로 전환한다. 첫 버전의 장비 상태 변경은 사람 승인 대상이다. 여러 Agent·LangGraph·MCP·벡터 DB를 먼저 추가하는 대안보다, 현재 단일 사건 조사에 필요한 작은 상태 머신과 SDK 직접 호출을 우선한다.

## AG002 — 제안: 사건/job 원자 등록, lease, 정확한 제안에 대한 승인

사건 생성과 Agent 작업을 같은 DB transaction에 기록하고 외부 LLM 호출 중에는 DB 잠금을 유지하지 않는다. lease token으로 작업 회수 후 늦은 워커 결과를 차단한다. 모델 호출 중복 비용까지 exactly-once로 주장하지 않는다. 승인은 대상·동작·인자·사건 revision·문서/정책 버전의 hash에 묶고 실행 직전에 현재 상태를 다시 검사한다. 현행 사건 생성 시 즉시 pending 조치를 넣는 분기는 assisted 모드에서 제거해 이중 조치를 방지한다. 현재 create_all만으로 기존 테이블 변경이 되지 않으므로 migration을 별도로 구현한다. 상세는 agent-platform-design.md를 따른다.

## AG003 — 1~7단계 구현: SDK 직접 호출·단계별 Tool 노출·명시적 출처

2026-10-17. 사용자의 7단계 구현 요청에 따라 단일 Agent를 공식 OpenAI Responses SDK로 연결했다. LangGraph/MCP/멀티 에이전트는 추가하지 않았다. 읽기·검색은 Pydantic Tool 계약, 미실행 의도는 submit_response_proposal, 실제 실행은 기존 executor가 담당한다. schema만으로 의미 정확성을 보장하지 않으므로 실제 LLM 합성 평가와 프로그램 테스트를 분리한다.

실제 평가에서 잘못된 문서 출처 ID·이른 제안 호출을 확인해 문서 ref의 패턴, snapshot의 명시적 ref, 선행 조회가 완료된 뒤의 제안 Tool 노출을 추가했다. 단순 프롬프트 지시보다 프로그램 검사와 제공 가능한 Tool 자체의 범위를 함께 관리한다. 이전 실패 기록을 보존하고 관측되지 않은 성능 수치를 쓰지 않는다.

## AG004 — 승인·영속성·현장 연동의 범위

assisted 모드에서는 사건 생성 시 기존 즉시 냉각 요청을 만들지 않는다. 정확한 제안 hash·만료·사건 revision·최근 데이터·문서·서버가 확정한 승인자 역할을 검증한 뒤 단일 action을 등록한다. shadow 모드는 기존 동작을 유지하며 Agent의 제안을 실행하지 않는다. 승인 토큰은 loopback 단일 운영자 인증이고 조직 RBAC/SSO가 아니다. 가상 장비 밖의 제어는 지원하지 않는다.

기존 데이터를 보존하는 두 순서형 migration과 checksum 이력, lease/token 기반 작업 회수, 완료·제안 원자 저장을 구현했다. 네트워크 호출 중 transaction을 유지하지 않는다. 재시작은 snapshot부터 새 attempt이며 LLM 비용의 exactly-once나 중간 턴부터의 재개를 보장하지 않는다. 반복 실패 작업이 다음 작업을 막지 않게 했다. 수동 재분석 이유와 인증된 요청자도 별도 migration으로 보존한다.
