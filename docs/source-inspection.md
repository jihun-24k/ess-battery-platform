# 1단계: 원천 MAT 구조 조사

조사일: 2026-10-17 (Asia/Seoul). 기존 Notebook과 과거 분석 코드는 탐색·분석·실행하지 않았다. 이번에 작성한 일회성 조사 명령으로 원본을 읽었다. ETL 함수나 DB 스키마는 구현하지 않았다.

## 조사 대상과 범위

프로젝트 루트에서 아래 파일을 발견했다. Batch 번호는 파일 자체의 필드가 아니므로 날짜와 번호의 대응은 아래와 같이 **제안**하며 사용자 확인 후 입력 설정에 고정한다.

| 제안 구분 | 실제 파일명 | 크기(bytes) | 셀 | 사이클 참조 합계 | 셀별 사이클 수 범위 | cycle_life NaN 셀 |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| Batch 1 | `2017-05-12_batchdata_updated_struct_errorcorrect.mat` | 3,025,320,241 | 46 | 38,811 | 533–1,226 | 0 |
| Batch 2 | `2018-02-20_batchdata_updated_struct_errorcorrect.mat` | 2,022,599,329 | 47 | 26,904 | 101–1,252 | 8 |
| Batch 3 | `2018-04-12_batchdata_updated_struct_errorcorrect.mat` | 3,236,690,412 | 46 | 51,007 | 540–2,237 | 2 |
| 추가 파일/포함 여부 미정 | `2018-04-03_varcharge_batchdata_updated_struct_errorcorrect.mat` | 89,125,795 | 2 | 1,053 | 240–813 | 2 |

주요 3개 파일 합계는 139셀, 116,722개 사이클 참조다. 이것은 원본에 저장된 구조상의 개수이며 품질 검증을 통과한 학습 데이터 개수가 아니다. 셀 제외, 배치 간 연결, 수명 보정은 하지 않았다.

전체 셀의 메타데이터·summary 값과 모든 사이클 참조의 null 여부를 조사했다. 파형은 셀마다 첫·중간·마지막 사이클을 읽었다. 주요 3개 파일은 417사이클, 추가 파일은 6사이클이다. 표본 밖 파형의 참조 대상과 값까지 읽지는 않았다. 따라서 전체 파형 무결성을 보장하지 않는다.

기계 판독용 근거는 [mat-inspection.json](mat-inspection.json)에 저장했다. 파일별 SHA-256, shape, dtype, 셀별 통계와 파형 표본 결과, 조사 실행 환경이 들어 있다. NaN 수명은 JSON 숫자가 아닌 문자열 `"nan"`으로 명시해 보존했다. 이는 조사 보고서 표현이며 향후 ETL의 결측 표현을 확정한 것이 아니다.

모든 MAT 파일은 `h5py.File(path, 'r')`로 열었다. 조사 전후 크기와 수정 시각은 같았다. 원본을 이동·수정·삭제하지 않았다.

## 실제 내부 구조

4개 모두 MATLAB v7.3/HDF5다. 공통 루트는 `#refs#`, `#subsystem#`, `batch`, `batch_date`다. `#refs#`는 셀 목록이 아니라 참조 대상 저장 공간이므로 해당 그룹의 항목 수를 셀 수로 세면 안 된다.

`batch`는 MATLAB struct이고 다음 8개 필드는 모두 `(셀 수, 1)`의 HDF5 object reference 배열이다. 참조를 역참조해야 실제 값/그룹을 얻는다.

| batch 필드 | 실제 참조 대상 | 해석/주의 |
| --- | --- | --- |
| `policy` | uint16, MATLAB char 벡터 | UTF-16 문자 데이터로 조사; 원문 유지 |
| `policy_readable` | uint16, MATLAB char 벡터 | 표시용 정책 문구; policy에서 새로 생성하지 않음 |
| `barcode` | uint32 `(1, 6)`, MATLAB string 객체 표현 | 숫자 배열을 barcode 값으로 간주하면 안 됨 |
| `channel_id` | uint32 `(1, 6)`, MATLAB string 객체 표현 | 채널 번호로 임의 해석 금지 |
| `cycle_life` | float64 `(1, 1)` | NaN 존재; 기록된 사이클 수와 다를 수 있음 |
| `Vdlin` | float64 `(1, 1000)` | 셀 수준 배열; 단위/의미는 추가 근거 전 보정하지 않음 |
| `summary` | 그룹 | 아래 8개 사이클별 수치 벡터 |
| `cycles` | 그룹 | 아래 9개 파형 참조 배열 |

summary 필드는 `IR`, `QCharge`, `QDischarge`, `Tavg`, `Tmax`, `Tmin`, `chargetime`, `cycle`이며, 각 셀에서 모두 float64 `(1, N)`이다.

cycles 필드는 `I`, `Qc`, `Qd`, `Qdlin`, `T`, `Tdlin`, `V`, `discharge_dQdV`, `t`이며, 각 셀에서 모두 object reference `(N, 1)`이다. 각 참조는 실제 파형을 가리킨다.

표본에서 비어 있지 않은 파형은 수치 벡터였다. `I/Qc/Qd/T/V/t`는 같은 사이클에서 길이가 같았으며 사이클마다 길이가 달랐다. `Qdlin/Tdlin/discharge_dQdV`는 비어 있지 않은 표본에서 각각 1,000점이었다. 원시 파형 길이와 1,000점 파형 길이를 같다고 강제하면 안 된다.

## 설계를 바꾸는 실제 관측

### 1. 첫 사이클의 빈 배열

`2017-05-12`의 46셀 모두 첫 사이클의 9개 파형에 `MATLAB_empty=1`이 있었다. 이 데이터셋의 저장 shape `(2,)`와 payload는 MATLAB 빈 배열의 차원 정보다. 두 개의 실제 측정값이 아니다.

추출기는 속성을 먼저 확인해 빈 수치 배열로 표현하고, 원천 위치와 빈 배열 사실을 보존해야 한다. 첫 사이클을 일괄 삭제하거나 이후 사이클 번호를 당기지 않는다. 파형이 비어 있어도 summary가 존재한다는 점을 별도로 다룬다.

### 2. cycle_life와 기록 수의 차이

- `2017-05-12`: 46셀 모두 `cycle_life = 사이클 참조 수 + 1`.
- `2018-02-20`: 8셀 NaN. 나머지 39셀은 cycle_life가 사이클 참조 수보다 15–66 작다.
- `2018-04-12`: 2셀 NaN. 나머지 44셀은 `cycle_life = 사이클 참조 수 + 1`.
- 추가 varcharge 파일: 2셀 모두 NaN.

`cycle_life`를 데이터 길이로 대체하거나 둘의 불일치를 즉시 구조 오류로 판정하지 않는다. NaN이 있는 셀도 원천 레코드로 보존할 수 있으며, 이후 학습용 수명 라벨 사용 가능 여부와 구분한다. 차이가 생긴 원인은 이번 조사만으로 확정하지 않았다.

### 3. 문자열 객체

`barcode/channel_id` 참조 대상에 `MATLAB_class=string`, `MATLAB_object_decode=3`이 있었다. 일반 uint16 char와 다른 직렬화 표현이며 `#subsystem#/MCOS`도 존재한다. 이번 조사에서는 의미 있는 식별 문자열로 해독하지 않았다.

초기 설계에서는 원천 해시 + 셀 위치를 기술적 식별자로 쓰고, 이 객체의 원시 payload·dtype·속성·참조 경로와 원본 파일을 보존한다. 표시값은 미해독 상태로 구분한다. 배치 간 같은 물리적 셀의 관계는 확인되지 않았으며 자동 병합하지 않는다.

### 4. summary의 유한한 값도 품질 검토 필요

전체 summary에는 NaN/Inf가 없었다. 그러나 `2018-02-20`에서 `Tmin=-270`, `Tmax=400`, 일부 필드에서 0 등이 관측됐다. 추가 파일의 IR은 모두 0이었다. 이것들이 센서 오류/결측 대체값인지, 어떤 단위인지는 아직 확정하지 않았다. 관측 결과만 기록하고 삭제하거나 0을 결측으로 치환하지 않았다.

### 5. 구조 일치가 의미 정합성을 증명하지 않음

모든 셀에서 summary 길이와 9개 사이클 참조 배열 길이가 같았다. `summary.cycle`은 1부터 N까지 연속이었다. 모든 사이클 필드의 null reference 수는 0이었다. 하지만 null이 아니라는 사실이 참조 대상 전체의 손상 없음까지 보장하지는 않는다.

이 결과는 위치에 따른 결합 설계를 뒷받침하지만 각 파형과 summary의 물리적 의미/단위까지 증명하지 않는다. Python의 0-based 저장 위치와 원천 `summary.cycle` 값을 모두 보존한다.

## 기술 조사와 발생한 오류

- `file *.mat`로 4개 파일의 MATLAB v7.3 형식을 확인했다.
- 기본 `python3`에는 NumPy/SciPy/h5py가 없었다. uv로 일회성 h5py 환경을 마련했다. 기본 uv 캐시 접근은 sandbox에서 거부돼 승인된 실행으로 준비했다. 프로젝트 의존성 파일은 아직 만들지 않았다.
- 다른 기존 임시 환경에서는 h5py import가 실패했다. 실제 설치된 환경의 interpreter로 조사했고 그 버전은 JSON에 기록했다. 이는 원천 파일 손상 오류가 아니다.
- 최초 shape 탐색 후 `MATLAB_empty` 속성을 추가 확인했다. 빈 배열의 차원 payload를 파형 데이터로 해석하지 않도록 보고서에 `logical_sample_count=0`을 추가하고 범위/시간 통계를 보정했다.
- 본 프로그램의 Python 3.11 호환성, PostgreSQL 접속과 적재는 아직 검증하지 않았다.

SciPy 공식 문서는 `loadmat`이 MATLAB 7.3 인터페이스를 제공하지 않으며 별도 HDF5 라이브러리가 필요하다고 설명한다: [scipy.io.loadmat](https://docs.scipy.org/doc/scipy/reference/generated/scipy.io.loadmat.html). 따라서 실제 구현에는 제시한 기본 스택에 **h5py 추가**가 필요하다. 참조 처리 방식은 [h5py object references 문서](https://docs.h5py.org/en/stable/refs.html)를 참고했다. 외부 분석 코드는 재사용하지 않았다.

## 실행한 검증과 실행하지 않은 테스트

실제로 수행한 것은 읽기 전용 구조 조사와 통계 확인이다. 4개 파일 모두 열기/해시 계산/전체 셀 메타데이터 읽기/전체 summary 읽기/참조 null 검사/423개 사이클 표본 파형 읽기가 완료됐다. 표본의 원시 파형 간 길이 불일치와 비유한 파형 값은 관측되지 않았다. 빈 배열을 제외한 표본 t에서 역행/중복 시각도 관측되지 않았다.

Pytest, Ruff, 손상 파일 테스트, 누락 필드 테스트, 전체 파형 값 검증, DB 통합 테스트는 실행하지 않았다. 아직 ETL 코드와 테스트 대상 함수가 없으며 이 보고서는 테스트 통과 선언이 아니다.
